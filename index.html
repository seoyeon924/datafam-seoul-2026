2.2 프롬프트 방식의 한계

두 번째 프로젝트부터 커지는 비용

매번 드는 비용

  • 같은 프롬프트를 프로젝트마다 다시 입력
  • 앞 답변이 길어지면 순서 누락
  • 중간에 끊기면 앞 단계부터 재실행

남지 않는 결과

  • 중간 산출물이 대화 안에 흩어짐
  • 지표 정의 재확인 어려움
  • 사람마다 달라지는 작업 기준

2.3 Agent · Rule · Skill

프롬프트 입력 대신 역할과 기준 미리 정의

AGENT

단계별 역할

단계별로 읽을 것과 남길 것을 사전 정의. 사람이 순서를 기억할 필요 없음

RULE

공통 분석 기준

모든 단계에 동일 기준 적용. 지표 정의 우선, 절대값과 상대값 혼용 금지, 카드 제목은 결론형 또는 질문형

SKILL

실행 순서

실행 순서와 실패 시 재개 지점의 문서화

한 번 정의역할 · 기준 · 순서
데이터 교체다음 프로젝트 투입
같은 흐름 재실행정의는 그대로

3.5 연결 방식

환경에 따라 두 갈래

TABLEAU CLOUD

공식 호스팅 서버

{ "mcpServers": { "tableau": { "url": "https://mcp.tableau.com" } } }
OAuth 2.1 로그인 · 기존 계정 권한 그대로 적용 · 설치 불필요
TABLEAU SERVER · 제한 환경

셀프 호스팅

$ npx -y @tableau/mcp-server@latest env SERVER · SITE_NAME · PAT_NAME · PAT_VALUE
서버 직접 구동 · 개인 액세스 토큰 인증 · 망 제약 환경용

4.1 기본 차트로
어려운 시각화

  • 인물 사이의 관계처럼 노드와 연결선으로 봐야 하는 데이터
  • Tableau 기본 차트로 표현 불가
  • Claude Code로 제작한 D3 기반 뷰 확장
  • Source · Target · Strength · Type 선반 연결로 동작
별도 대시보드가 아닌 Tableau 워크시트 내부 실행

4.2 Tableau 안에서
실행되는 결과

  • 워크시트 Marks 카드에 확장 추가
  • 선반에 필드 연결 시 즉시 렌더링
  • 데이터 교체 후에도 동일 확장 동작
AI가 Tableau를 대신한 것이 아니라,
Tableau가 할 수 있는 일을 넓혔다.

Claude Code는 반복되는 분석 절차를 재사용 가능한 워크플로우로 만들고,
